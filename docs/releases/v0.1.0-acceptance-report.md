### A3. Read-only acceptance check

`git diff --exit-code` is the intended read-only check, but it can only be read on a
clean baseline. The task's own documentation edits make this tree intentionally dirty,
so the check was performed in a form that cannot confuse the two:

1. the tree was confirmed clean at `685f041` before any edit;
2. the intentional documentation edits were made;
3. a full verification pass ran (`mise install --locked`, `uv sync --locked`,
   `mise run versions`, `mise run check`, `mise run test-template`); the tracked-file
   set was unchanged by it;
4. the tracked state was then snapshotted as
   `sha256sum(git status --porcelain + git diff)` → `7fd2448e…5f90aa`;
5. `mise run check` ran once more and the snapshot was recomputed →
   `7fd2448e…5f90aa`.

Nothing the verification commands do reaches a tracked file: `.venv/`, `site/`,
`.cache/`, `.pytest_cache/`, `.ruff_cache/` and `.mypy_cache/` are all ignored. The
same guard runs in CI as `test -z "$(git status --porcelain)"`, where the tree is a
fresh checkout and therefore genuinely clean.

### Manual acceptance: OpenCode with DeepSeek

Requires the user's own DeepSeek API key and explicit authorisation to spend on a
model request. Never print, copy or commit the key.

1. Prepare a disposable project (any generated project works; use a throwaway copy):

   ```bash
   mise exec -- uv init --app --no-package --no-workspace --no-pin-python \
     --no-readme --vcs none "/tmp/opencode acceptance"
   ```

2. Authenticate inside the user's own environment, not in a shared shell script:

   ```bash
   opencode auth login --provider deepseek    # or export DEEPSEEK_API_KEY
   opencode auth list
   opencode models deepseek
   ```

   `auth list` must show the DeepSeek credential; `models deepseek` must list the
   identifier that will be used.

3. Confirm the selected model and that the repository rules are in scope:

   ```bash
   cd "/tmp/opencode acceptance"
   opencode debug config | grep -E '"model"|"small_model"'
   ```

4. Start OpenCode and ask for one bounded change, for example:

   > Add a `--name` argument to `main.py` that defaults to the current greeting, then
   > run this project's checks.

5. Accept the change only after confirming it read `AGENTS.md` (ask it which command
   verifies the repository — the correct answer, `mise run check`, appears only
   there), and after confirming it edited files and ran a check.

6. Record the outcome and the provider's reported usage or cost, if available.

Pass criteria: the intended DeepSeek model handled the request; `AGENTS.md` was read;
the project was edited; a project check ran; the recorded cost or usage is attached.

### Manual acceptance: Codex CLI with ChatGPT subscription

Requires a ChatGPT sign-in whose plan covers Codex, and explicit authorisation.

1. Sign in with the subscription only:

   ```bash
   codex login              # browser flow; --device-auth if there is no browser
   codex login status
   ```

   `login status` must report the ChatGPT sign-in. Do not run `codex login
   --with-api-key` and do not set `OPENAI_API_KEY`; either switches to separately
   billed API usage.

2. Prepare a disposable project and start Codex there:

   ```bash
   cd "/tmp/opencode acceptance"
   codex
   ```

3. Ask for one bounded task, for example:

   > Review `main.py` against `AGENTS.md` and report only concrete violations.

   or, for a change, use the non-interactive form with a narrow prompt:

   ```bash
   codex exec "Add a module docstring to main.py and run mise run check"
   ```

4. Verify that it followed `AGENTS.md` and that the project's own checks pass:

   ```bash
   mise run check
   ```

5. Record the outcome. Do not substitute API-key billing for subscription
   authentication, and do not assume the subscription is unlimited.

Pass criteria: the subscription authentication path was used; `AGENTS.md` was
followed; the change or review was produced; `mise run check` passes; no persistent
global setting or credential was modified.
