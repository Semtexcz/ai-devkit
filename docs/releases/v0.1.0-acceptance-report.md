### A3. Read-only acceptance check

`git diff --exit-code` is the intended read-only check, but it can only be read on a
clean baseline. The task's own documentation edits make this tree intentionally dirty,
so the check was performed in a form that cannot confuse the two:

1. the tree was confirmed clean at `685f041` before any edit;
2. the intentional documentation edits were made;
3. a full verification pass ran (`mise install --locked`, `uv sync --locked`,
   `mise run versions`, `mise run check`, `mise run test-template`); the tracked-file
   set was unchanged by it;
4. the tracked state was then snapshotted as
   `sha256sum(git status --porcelain + git diff)` → `7fd2448e…5f90aa`;
5. `mise run check` ran once more and the snapshot was recomputed →
   `7fd2448e…5f90aa`.

Nothing the verification commands do reaches a tracked file: `.venv/`, `site/`,
`.cache/`, `.pytest_cache/`, `.ruff_cache/` and `.mypy_cache/` are all ignored. The
same guard runs in CI as `test -z "$(git status --porcelain)"`, where the tree is a
fresh checkout and therefore genuinely clean.

### Fixtures: a complete generated project, not a bare `uv init` project

Both tests need a project that actually carries the devkit's engineering rules and its
verification contract. A directory created by `uv init` alone does not: it has no
`AGENTS.md`, no `mise.toml`, no `mise run check`, no test suite and no OpenSpec
integration. Running an agent there and reporting the result would say nothing about
whether an agent follows this devkit, so that fixture is not used.

The fixture is therefore the **complete generated project**: native `uv init`, the
Copier overlay, the baseline development dependencies, both lockfiles, the documented
`main() -> None` edit and a native OpenSpec initialization. The procedure is
[Create your first Python project](../tutorials/first-python-project.md); it is not
copied here. The table below only says which tutorial step supplies what the fixture
needs.

```bash
  --no-readme --vcs none "$dest"
devkit="$PWD"
mise exec -- uv run --locked copier copy --vcs-ref HEAD --defaults "$devkit" "$dest"

cd "$dest"
mise exec -- uv add --dev 'ruff==0.17.3' 'mypy==2.4.1' 'pytest==9.2.0' 'zensical==0.0.74'
# tutorial step 4: edit main.py so that `def main():` becomes `def main() -> None:`
mise trust                                # addition: the project's mise.toml is new to mise
mise run lock-tools                       # writes mise.lock
mise install --locked                     # addition: install the toolchain the project pins
mise exec -- openspec init --tools opencode,codex --profile core
```

`--vcs-ref HEAD` renders the clean checkout; use `--vcs-ref v0.1.0` once that tag
exists. A dirty tree makes `.copier-answers.yml` unusable for later updates, so record
the commit the fixtures were rendered from. `mise trust` appears here because the
project's `mise.toml` is new to mise; the tutorial relies on mise's interactive prompt
for the same decision.

#### 2. Verify the base project, then make it a repository

A fixture that fails its own verification cannot evidence anything about an agent.

```bash
mise exec -- uv lock --check       # uv.lock matches pyproject.toml
mise run check                     # the generated project's own contract
```

A Git repository with a clean tree turns everything an agent does into a reviewable
diff (tutorial step 8):

```bash
git init && git add --all && git commit -m "Base project for agent acceptance"
git status --porcelain             # must print nothing
```

#### 3. Make two independent fixtures

```bash
mkdir -p "$HOME/acceptance"
cp -a "$HOME/acceptance/base project" "$HOME/acceptance/opencode"
cp -a "$HOME/acceptance/base project" "$HOME/acceptance/codex"
```

Each copy owns its `.venv/`, `uv.lock`, `mise.lock`, `openspec/`, `.opencode/` and
`.agents/`, so neither session can influence the other's result. Trust and re-verify
each copy at its new path before use:

```bash
for p in "$HOME/acceptance/opencode" "$HOME/acceptance/codex"; do
  ( cd "$p" && mise trust && mise run check && git status --porcelain )
done
```

#### 4. Confirm the fixture contents

```bash
for p in "$HOME/acceptance/opencode" "$HOME/acceptance/codex"; do
  printf '== %s\n' "$p"

        "$p/pyproject.toml" "$p/tests" "$p/openspec" "$p/.opencode" "$p/.agents"
done
```

`ls -d` prints every path that exists and reports a missing one on stderr, so a fixture
without `AGENTS.md`, `mise.toml`, `mise.lock`, `uv.lock`, the test suite or the OpenSpec
integration is visible before an agent runs. The `git status --porcelain` in step 3 must
stay empty.

#### 5. After each agent task

1. `git status --short` and `git diff` in that fixture — read what actually changed.
2. `mise run check` in that fixture — the generated project's verification contract, not
   a command of the agent's choosing.
3. Record one row in the table above: what was asked, what changed, the check's exit
   status and summary, and the usage or cost if the harness reports one.

An agent's statement that a check passed is not the check's result. Run it.

### Manual acceptance: OpenCode 1.19.5 with DeepSeek

**Authorisation gate.** This procedure authenticates a provider and makes a request that
is billed to the user's DeepSeek account. Confirm explicitly that you authorise both the
authentication and the paid inference before step 2. Without that authorisation the
OpenCode result stays **PENDING**: nothing in this repository substitutes for it, and no
task in `mise run check` sends a model request.

1. Work in the first fixture, from its root:

   ```bash
   cd "$HOME/acceptance/opencode"
   ```

2. Authenticate through OpenCode's own mechanism, inside your own environment:

   ```bash
   opencode auth login --provider deepseek
   opencode auth list
   ```

   `auth list` must name DeepSeek. That is the configuration check, not the execution
   check. The key lives in `~/.local/share/opencode/auth.json`: do not print it, copy it,
   commit it or move it into the project, and do not put it in a tracked `.env`.

3. Select `deepseek/deepseek-flash` explicitly, using the documented example
   `examples/agents/opencode.json` and **without overwriting your global
   configuration**. Either form is acceptable:

   - per run, naming the model on the command line:

     ```bash
     opencode run -m deepseek/deepseek-flash "…the prompt from step 7…"
     ```

   - or per project, by adding the two keys to the fixture's own `opencode.json`, which
     overrides the user file only for the keys it names:

     ```json
     {
       "$schema": "https://opencode.ai/config.json",
       "model": "deepseek/deepseek-flash",
       "small_model": "deepseek/deepseek-flash"
     }
     ```

   Never copy the example over `~/.config/opencode/opencode.json`. If a user file
   already exists, add the keys by hand as
   [Configure coding agents](../how-to/configure-coding-agents.md) describes.

4. Verify that the selection is *in force*, not merely present in an example file:

   ```bash
   opencode debug config | grep -E '"model"|"small_model"'
   ```

   With the project-file form, both keys must appear with `deepseek/deepseek-flash`. With
   the `-m` form the merged document will not contain the key, so the effective model is
   the one named on the command line; record the invocation and the model the session
   reports instead of this grep.

5. Confirm the identifier is available to this account:

   ```bash
   opencode models deepseek
   ```

   `deepseek/deepseek-flash` must be listed. If it is not, stop: do not silently
   substitute another model, another provider or another billing path.

6. Confirm the rules are in scope by asking a question whose answer exists only in
   `AGENTS.md`:

   > Which command verifies this repository?

   The expected answer is `mise run check`. A different answer means the rules were not
   loaded: stop and fix the fixture before spending more.

7. Run the one bounded task:

   > Add a `--name` argument to `main.py` that defaults to the current greeting, add a
   > test for it, and make `mise run check` pass.

   Keep it to one file plus one test. Refuse anything wider.

8. Verify the outcome yourself:

   ```bash
   cd "$HOME/acceptance/opencode"
   git status --short
   git diff
   mise run check
   ```

9. Record: the model the session reports, the diff summary, the check's exit status and
   summary, and the usage or cost if OpenCode or the provider reports it.

Pass criteria: the authorisation was given and recorded; a DeepSeek credential is in
OpenCode's own store; `deepseek/deepseek-flash` is the model that handled the request as
the session reports it; `AGENTS.md` was demonstrably read; the fixture was edited; the
project's `mise run check` ran and passed; the diff was reviewed; usage or cost is
recorded if available; no user-level configuration was overwritten and no credential was
copied. Until a run satisfies these criteria, this report keeps OpenCode at **PENDING**.
