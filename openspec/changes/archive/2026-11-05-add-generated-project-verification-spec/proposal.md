# Proposal

## Why

A generated Python script project already runs every check through `mise run check`, and OpenSpec is now part of its toolchain. Nothing states in a machine-checkable form what that command must do, so the contract exists only as a task list in `mise.toml` and as prose in the documentation. A reader cannot tell which failures are required behavior and which are incidental.

## What Changes

State the verification contract as a behavioural requirement of a generated project, so the specification, the tutorial and the generated `mise.toml` describe the same observable outcome. No code changes: the behavior already exists in the overlay.

## Capabilities

### New Capabilities

- `generated-project-verification`: what a Python script project generated by this devkit must be able to prove about itself

### Modified Capabilities

## Impact

- `openspec/specs/generated-project-verification/spec.md` (created by archiving this change)
- `docs/tutorials/first-python-project.md`, `docs/tutorials/spec-driven-change.md`, `docs/reference/openspec.md`: the documentation that describes the contract
